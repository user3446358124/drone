# drone

基于 Swarm-Rescue-v4 的蓝方优化项目，当前代码为 `approach_v9` 实验候选。

## 这次改善了哪些层面

| 层面 | 原代码遇到的问题 | 本次采用的方法 | 预期作用及边界 |
|---|---|---|---|
| 搜索覆盖 | LiDAR约300像素可见，不等于约200像素语义传感器已检查过炸弹 | 把语义覆盖采样上界修正到182像素，保留原共享前沿搜索 | 减少把尚未检查的空间误认为已经搜索；原巡航框架仍未全面重写 |
| 在线障碍地图 | 动态炸弹、无人机可能留下旧墙证据 | 确认射线命中动态对象时，只清理端点格子的旧墙假设 | 减少虚假障碍，同时避免大片删除附近真实墙体 |
| 目标关联 | 远距离观测噪声可能把同一炸弹重复建成多个任务 | 按观测距离调整关联半径；平滑队友报告的目标中心 | 降低重复追踪和无效接近；很近的不同炸弹仍有误合并风险 |
| 多机接近协作 | 多架无人机争抢同一片区域，引擎又允许多人附着同一炸弹 | 接近区域预约、编号裁决和已有载荷优先 | 减少机间碰撞与共同拖拽；预约可能降低相邻任务并行度，负责人切换仍需优化 |
| 接近目标 | 目标可见时仍可能有墙角阻挡，直接转向前冲容易碰撞 | 目标距离大于65像素时使用在线路径，近距离再对齐抓取 | 把绕障与抓取姿态分开处理 |
| 抓取时机 | 抓手常开可能接触错误目标或产生多人共同附着 | 启动阶段结束、距离≤35像素且角度对齐才开启；检查更近的其他炸弹 | 减少错误附着；本版本没有保留“逐目标连续等待4步”的试验 |
| 载荷返航 | 附着炸弹增加惯性和空间要求，转向再前推可能卡住 | 区分空载20/载荷32像素膨胀；载荷在线路径采用已有侧向移动，保留轨迹与局部绕行兜底 | 改善部分返航场景；固定膨胀不能完整描述载荷摆动，窄口可能变慢 |
| 停车与逃逸 | 零平移输入不会立即停车；已排队逃逸可能被计数条件挡住 | 按测得速度主动制动，修复逃逸动作执行条件 | 减少等待和对齐时漂移，提高卡住后的恢复机会 |
| 规划计算 | 定位抖动导致频繁重规划，障碍膨胀有计算开销 | 距离变换膨胀障碍；设置目标变化重规划间隔，区分空载和载荷周期 | 降低无效计算；有限预算加权A*仍不保证全局最短路径 |

以上阈值依据现有传感器和物理尺度设置，没有按地图编号为新增规则单独调参。这是多项改动的组合评测，尚未逐项消融，不能把得分提升准确归因给某一个组件。

主要控制源码改动：

- [my_drone_rescue_example.py](src/swarm_rescue/solutions/my_drone_rescue_example.py)：目标、预约、抓取、返航及状态机调用。
- [online_mapping.py](src/swarm_rescue/solutions/online_mapping.py)：动态对象端点证据清理。
- [online_navigation.py](src/swarm_rescue/solutions/online_navigation.py)：障碍膨胀计算。
- [motion_control.py](src/swarm_rescue/solutions/motion_control.py)：主动制动辅助函数。

地图、仿真物理、碰撞扣血与评分源码没有改变；新增的 WSL 配置和脚本用于启动、复现和评测。

### 如何理解这些成绩

- **Map01历史布局显著改善。** 主种子从9/10、2000步、70.44分，改善到10/10、1309步、93.14分；第二种子也提高3.20分。
- **Map05历史布局保住了更多健康。** 主种子健康75.8%→87.0%，完成步数2389→1922，得分95.16→97.40；第二种子得分提高1.72分。
- **退步没有隐藏。** 主种子的Map05相邻布局下降12.16分；第二种子的Map01分层布局下降10.30分，少归位一枚；独立Map07下降8.37分。
- **保健康不能脱离时间代价。** Map07健康46.2%→59.6%，但完成步数5276→7928，时间损失超过健康收益。

蓝方评分为 `0.6×归位百分比 + 0.2×健康百分比 + 0.2×时间分`。
时间分在一半步数预算内封顶，之后线性下降：Map01的满时间分门槛是1000步，Map05是3600步。
用户最初的Map01成绩1951步、健康90.2%、全部归位，实际得分为 `60+18.04+0.98=79.02`，主要损失在时间。

### 评测条件与限制

- 10架无人机、10枚炸弹、特殊区域关闭，各场串行运行；WSL Python 3.11.16、Arcade 2.6.17。
- 每组比较使用相同布局和仿真随机种子。主种子的原版先成批运行，候选随后运行；第二种子和Map07采用原版、候选交替串行运行。
- 引擎碰撞扣血使用真实时间冷却，固定种子也不保证不同机器和负载下完全一致。以上为已测场景的描述统计，不是未知地图分布的性能保证。
- 第二种子没有重新生成固定布局，不能替代任意红方新布局测试；继承的控制器仍有尺寸/编号相关巡航和固定10枚任务假设。
- 候选此前通过70项相关测试及提交检查。组件测试通过不代表比赛表现一定改善。
